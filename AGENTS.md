# Architecture rules
- Gift recipient responses are separate from owner reviews: capability-validated submission, one response per gift, owner-only reads and acknowledgment; sender email identity is resolved server-side and admin-test gifts never send response emails.
- Gift feedback reuses ReviewForm and ReactionVideoUpload on the owner's released-gift tracking page, associated with the source/production music order, never the card-only checkout order.
- Normalize gift social sharing to the static gift entry page; preserve private keys and continue accepting legacy URLs.
- Recipient gift creation links to the existing digital gift wizard without copying private gift data; native share and copy-message use the same complete payload as WhatsApp to retain text and link across apps.
- Keep gift marketing on the homepage and recurring-plan marketing on the lazy-loaded /criadores page; reuse existing checkout flows to avoid billing changes.
- Read commercial plan values from pricing_config and show an unavailable state on fetch failure; never fabricate purchasable fallback prices or credits.
- Keep marketing translations in the home/pricing namespaces for all four supported languages and use the existing currency formatter.
- Resolve legacy Creator campaign hashes at the router boundary without redirecting ordinary package visitors.
- Classic Vite serves one static head to non-JavaScript crawlers; route SEO is client-side and must not be represented as server-rendered social previews.- Briefing entry is purpose-first; purpose→musicType/route mapping lives only in src/lib/briefingPurpose.ts (tested) so quick orders are never silently classified as homenagem.
- IT/EUR sandbox checkout is isolated (it_test_* tables, create-it-test-checkout, stripe-it-test-webhook, STRIPE_IT_TEST_* secrets); only the signed sandbox webhook marks orders paid, prices come from it_test_catalog, and Brazilian checkout code/keys are never reused.
- IT sandbox purchases snapshot the owned briefing and fulfill into separate is_preview/is_test copies; a test payment must never mark the original Brazilian order or card paid. Sandbox markers are immutable, and server notification/tracking endpoints must suppress these copies.
